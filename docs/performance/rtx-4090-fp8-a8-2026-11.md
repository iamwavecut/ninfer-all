# RTX 4090 FP8 A8 prefill route, November 2026

The sm_89 plain-E4M3 tensor-core A8 prefill route for `FP8_E4M3FN_ROW_BF16` weights, built with
`CMAKE_CUDA_ARCHITECTURES=89` and the `NINFER_SM89_FP8` option (on by default; `OFF` rebuilds the
dequantizing A16 behavior), measured on an RTX 4090 with 48 GB and its e4m3 rate unlocked. The
model is `Qwen3.8-27B-FP8-v3-full.ninfer` (27B, 64 layers, 48 GDN linear-attention + 16 full
attention). A8 touches only the prefill GEMMs of the five registered shapes; decode runs the same
FP8 weight bytes and is bandwidth-bound, so it is unchanged by design. The setup is at the
[end](#how-these-were-measured).

`ninfer-perplexity` on `ninfer-ppl-1m-v1`, KV `int8-g64`, context 4,096, stride 2,048; the A16
build ran with every one of the 513 stored A8 permissions demoted, the A8 build kept all 513.
Perplexity went up by less than a sixth of a percent, on the quick slice and on the full corpus

## Op level: A8 against the A16 route

`fp8_linear_add_bench` with the policy forced per run (A8 or A16 regardless of the width gate),
Qwen3.8-27B's five GEMM shapes, 30 repeats per width with the L2 flushed between repeats. Each
cell is the A16 route's time divided by the A8 route's time at that width; above 1 is A8, below 1
is A16:

| width T | 14336×5120 | 16384×5120 (GDN) | 34816×5120 | 5120×6144 | 5120×17408 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.00 | 1.00 | 1.00 | 1.00 | 0.99 |
| 8 | 1.00 | 1.00 | 1.87 | 1.00 | 1.00 |
| 17 | 1.54 | 1.84 | 4.64 | 1.63 | 1.00 |
| 32 | 1.05 | 1.00 | 0.98 | 2.55 | 2.60 |
| 64 | 1.80 | 1.37 | 1.33 | 4.57 | 4.53 |
| 128 | 2.41 | 1.71 | 2.05 | 8.64 | 8.95 |
| 256 | 2.24 | 2.50 | 2.81 | 12.05 | 11.63 |
| 512 | 2.30 | 2.77 | 3.13 | 12.15 | 12.37 |
| 1024 | 2.39 | 2.83 | 3.34 | 14.44 | 14.64 |
| 2048 | 2.29 | 2.88 | 3.41 | 2.06 | 2.11 |

Two things in this table. Where the A16 route is its normal self, A8 wins by 1.3–3.4× from T=32 up
on the K=5120 shapes; the 5120×6144 and 5120×17408 projections sit on a dequantizing chunked
route that collapses at mid width (up to 16× at T=768) before recovering at 2048. And the A16
route has pathologies of its own that set the width gate: it is 1.86× *slower* than A8 at T=5–8 on
34816×5120 (the DFlash2 verify width, where A8 must be used), it spikes to 4.64× slower exactly at
T=17 on 34816 and 1.5–1.8× slower on the other K=5120 shapes, and all five shapes spike at T=384
(10–48× slower than at T=256). The measured `uses_a8` gate per shape keeps A16 below its slow
widths and A8 above them:

| shape | A8 from | note |
|---|---|---|
| 14336×5120, 16384×5120 | T=17 or T≥32 | A8 at T=17 only, because the A16 route is pathologically slow exactly there; A16 wins by 4–6% at T=20–25; A8 by ≥5% from T=32 |
| 34816×5120 | T=1 or T≥3 | A16 is 1.86–1.87× slower than A8 at T=5–8 (the verify width); A16 wins by 2–6% at T=12–32, which the gate leaves to A8 |
| 5120×6144 | T≥17 | the A16 route is normal at T≤16 (ties) and collapses from T=17 (1.63–16×) |
| 5120×17408 | T≥20 | normal to T=17 (tie), collapses from T=20 (1.8–16×) |

## Schedules

Eleven plain-MMA schedules (token/row/K tile sizes, stage counts, pipeline, raster order and
blocks-per-SM) were swept on every shape at 26 widths (1 to 2048) with the L2 cold, median of 9.
The schedule the 120a build ships was never the measured winner at any width of any shape; at its
best it sat 2–25% behind the winner. Each shape now selects its measured winner per width; the
selections live in the shape sources and the fused-Op sources. The winners:

| shape | T ≤ 64 | T ≤ 192 | T ≤ 256 | T ≤ 384 | T ≤ 512 | T ≥ 1024 |
|---|---|---|---|---|---|---|
| 14336×5120, 16384×5120 | — | K tile 256 | | | | tokens 128 (from T=256) |
| 34816×5120 | rows 64 | K tile 256 | tokens 128 (from T=256) | | | |
| 5120×6144 | rows 64 | K tile 256 | warps 1 | tokens 128 | K tile 256 | tokens 128 |
| 5120×17408 | | K tile 256 | warps 1 | tokens 128 | K tile 256 | tokens 128 |

(the gate widths apply first; below them the A16 route runs). The fused SwiGLU projection uses the
34816×5120 winners; the two fused residual projections use the 5120×6144 and 5120×17408 rows; the
GDN input projection and the generic 16384×5120 shape use the first row.

## End to end

The perplexity scoring rate above is the end-to-end A8-against-A16 comparison: the same corpus,
the same KV format, one activation-policy flag apart, 1.28k → 2.99k tokens/s (2.33×) on a
prefill-bound workload.

Serve load test, one lane, the A8 build with DFlash2 (5 drafts), disk KV cache cold at the start
of the run (per-run nonce): a cold prefill of 14,363 tokens ran at 4.28k tokens/s with a first
token at 3.4 s; four concurrent lanes held 4.05k tokens/s aggregate (first token 3.4 → 14 s) at
127–137 tokens/s per lane, DFlash2 acceptance 87–94%; a single 94,716-token prefill ran at 2.02k
tokens/s (first token 48.4 s). A repeat run on the rebuilt binary measured 3.98k tokens/s cold
prefill and 91.6–122 tokens/s per lane of decode. The A16 build was not serve-load-tested; the
perplexity run is the end-to-end A16 comparison.

## How these were measured

- Card: RTX 4090, 48 GB, sm_89, its e4m3 tensor-core rate unlocked with nv-uefi-unlocker (volatile
  across cold boot; every measurement window opens with an `ssdiag` readout confirming the gate).
  The locked state runs the same numerics at a lower rate and is not represented here.
- Toolchain: MSVC 14.51.36231, CUDA 13.4.59, CMake 4.4.4, Ninja, Release. A8 build with
  `NINFER_SM89_FP8=ON`, A16 build with `OFF` (verified by the absence of the macro in the A16
  build's compile commands); the two builds differ only in that option.
- Op sweeps: `ninfer_fp8_a8_schedule_bench <shape>` (11 schedules × 26 widths, L2 cold, median of
  9, production route measured as the `public_op` column); T-curves:
  `ninfer_fp8_linear_add_bench --k 5120 --rows <shape> --policy a8|a16` (30 repeats, L2 flushed
  between repeats, policy forced).
- Perplexity: `ninfer-perplexity <artifact> --corpus eval/corpora/perplexity-1m/manifest.json
  [--quick] --kv-dtype int8 --output <dir>`; the model prints its activation policy at load
  (A8: kept 513, demoted 0; A16: kept 0, demoted 513).
- Suite: the 371-test CTest set, one test at a time, 600 s per-test timeout, GPU dedicated
  (production serving stopped for the window).
- Windows host with a Low-integrity workspace; test executables run from `F:` under a runner that
  redirects the test children's temporary directory into the workspace.
